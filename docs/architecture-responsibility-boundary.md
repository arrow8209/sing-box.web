# 为什么改一处要动很多文件

> 本文已被[前后端职责与配置引用优化方案](frontend-backend-responsibilities-and-migration.md)取代。其中「档案只记编号」「每一步都能单独上线」「服务器只是检查、复制文件」等表述以新文为准。下文保留当时的问题说明，便于对照，不再作为实施步骤。

用一件刚做过的事说明。

## 你要的，其实就四句话

1. 页面负责给人看、给人改。
2. 计算和整理数据，放服务器。
3. 入站页管入站，订阅页管订阅，工作台管当前配置。彼此只知道对方的编号，不要掺对方的业务。
4. 你说「同步一下引用」，就该只改「同步」这一处。

现在不是这样。

## 先讲一件具体的事

你最近要的是：点预览、检测、应用之前，把订阅和入站源的最新内容灌进当前配置。

按你的设想，流程应该是：

```
你点「应用」
  → 浏览器告诉服务器：用当前这份配置去应用
  → 服务器自己去读订阅、读入站库，整理好，再检查、再写入
```

实际流程是：

```
你点「应用」
  → 浏览器先去拉订阅、拉入站库
  → 浏览器自己把节点展开、把入站拷进配置、再改路由
  → 浏览器把整理好的结果存一遍
  → 再告诉服务器：用我刚存好的这份去应用
  → 服务器不再整理，只是检查并复制文件
```

计算发生在浏览器里。所以「同步引用」不是改服务器一处，而是：

- 应用按钮那边要先跑同步
- 出站编辑器要知道怎么展开订阅
- 入站工作台要知道怎么绑源、怎么写嗅探规则
- 入站库的对话框也要跟着改（因为工作台在用它）
- 单测、浏览器测试、说明文档、版本号再各改一遍

这一次实际改了 20 个文件。

规则集没有这个问题。规则集页只保存「用哪条规则、叫什么名字」。真正变成 sing-box 文件，是服务器在生成配置时做的。入站和订阅没有走这条路。

## 对照你的四点

**1. 前后端分离**

表面上分开了：页面是 Vue，服务是 Go。

但页面不只是在改数据，还在做整理：把订阅展开成节点列表、把入站源拷进档案、把旧嗅探改成路由规则。服务器拿到的已经是整理完的成品，它主要负责存盘、检查、复制、管核心进程。

**2. 处理放后端**

服务器确实在处理「存、查、跑、更新」。

「这份配置实际长什么样」是浏览器算的。所以大部分你在意的数据处理，不在后端。

**3. 页面独立**

菜单上是分开的：入站配置、订阅配置、配置工作台。

底下共用一份正在编辑的配置。工作台改入站时，会去改路由；点应用时，会去读订阅库和入站库；仪表盘选节点时，还会去看出站那套整理逻辑。

这不是「入站页告诉工作台一个编号」，而是几个页面在共用同一套整理代码。

还有一句和功能相反的文案：入站库页面仍写「导入后互不联动」，工作台却已经做成关联并在应用前同步。

**4. 一次需求改一处**

改界面样子，有时真的只改一个文件。

一改「配置是什么意思」，就要同时改：

- 编辑页面
- 整理数据的脚本
- 应用按钮
- 可能被牵连的另一个页面
- 单元测试
- 浏览器测试
- 说明和版本号

不是开发不小心，是数据整理散落在这些地方，漏一处就会错。

## 这样会有什么实际问题

不只是改得多。

「整理」只在你点按钮时、由当前这个网页做。如果网页没先整理（比如自动重载、或另一处直接去应用），服务器会用旧内容去检查。订阅改了、入站源改了，正式配置可能还是旧的。

## 怎么改才对得上你的设想

不重写整个项目。按规则集已经做对的方式，把入站和订阅也改成：

```
页面只保存：用了哪个订阅 / 哪条入站，本地叫什么名字
你点预览、检测、应用
  → 服务器去读源、整理、再检查
```

分三步，每一步都能单独上线。

**第一步：把「点应用前的同步」搬到服务器。**  
浏览器不再先算一遍。点预览/检测/应用，服务器自己去拉订阅和入站源。这一步专门消化刚做的那次 20 文件改动。做完以后，再改同步规则，主要改服务器一处。

**第二步：入站、订阅改成和规则集一样，只记编号。**  
不要先拷一份 JSON 到档案里，再靠网页去回刷。档案里只记「引用了谁」。展开仍由服务器在应用时做。

**第三步：拆开配置工作台。**  
入站库只维护入站源。工作台只展示当前档案里的入站，关联时只传编号。不要共用对方的内部整理代码。

明确不做：不把填表搬到服务器；不上全新一套前端；不一次把 DNS、路由的所有表单逻辑都搬走。先搬「应用时必须算对」的那部分。

## 改完之后，你提需求会长什么样

| 你说 | 现在 | 改完 |
| --- | --- | --- |
| 入站表单加一个框 | 对话框、工作台、整理脚本、测试，可能还有同步 | 主要改入站表单 |
| 订阅变了要反映到选择组 | 同步脚本、出站整理、应用按钮、两层测试 | 主要改服务器整理 |
| 应用前同步失败要提示 | 应用按钮、类型、工作台 | 服务器返回错误，按钮拿来显示 |

建议就从第一步做。它对应你已经做成的功能，只是放到正确的一层。
