# 真实 sing-box 人工协作测试方案

> 状态：待审核

## 1. 目标

人工协作测试用于验证必须与真实运行中的 sing-box、Clash API 或宿主机网络设置交互的功能。

该阶段由用户控制真实核心和所有可能影响网络的操作，Codex 负责准备测试用例、记录日志、整理结果、定位问题和修复代码。

只有对应 `config.json` 已通过[自动化测试方案](./automated-testing.md)后，才能执行本阶段测试。

## 2. 功能参考与边界

运行时功能参考 `../demo/GUI.for.SingBox` 中的以下调用链：

- `frontend/src/api/kernel.ts`：Clash API REST 和 WebSocket 接口。
- `frontend/src/stores/kernelApi.ts`：核心启动、停止、重启和运行状态。
- `frontend/src/views/HomeView/components`：流量、日志、连接和策略组控制。
- `frontend/src/stores/env.ts`：系统代理和系统 DNS。

参考项目仅用于罗列功能和交互方式。具体 API、配置字段及版本兼容性仍以 sing-box 官方文档为准。

以下功能不要求运行真实核心，不列入本方案：

- 配置表单编辑和 `config.json` 生成。
- 配置导入、导出和无损往返。
- 订阅下载、解析和节点数据管理。
- 规则集编辑、下载和定时任务本身。
- 界面主题、布局和纯本地偏好设置。
- 核心安装包的检查、下载和文件管理。

这些功能如果最终改变运行配置，其“应用到核心”部分仍需在本方案中验证。

## 3. 职责划分

### 3.1 用户负责

- 审核每次测试的步骤和可能影响。
- 启动或允许启动真实 sing-box。
- 操作 TUN、系统代理、系统 DNS 及其他可能影响宿主机网络的功能。
- 观察真实网络行为并指出异常或 Bug。
- 网络异常时使用事先准备的独立恢复方式恢复环境。

### 3.2 Codex 负责

- 每次只准备和执行一个明确的测试用例。
- 测试前说明前置条件、操作步骤、预期结果和停止条件。
- 在用户授权的范围内收集前端、API 和 sing-box 日志。
- 对配置、请求和日志中的敏感信息进行脱敏。
- 将用户指出的问题记录为可复现的 Bug。
- 先补充自动化回归测试，再进行代码修复。
- 修复后请求用户重复原人工用例进行确认。

Codex 不得自行启用 TUN、系统代理或系统 DNS，也不得在用户失联时继续扩大测试范围。

## 4. 测试前置条件

每次人工测试会话开始前必须记录：

- 当前代码提交或工作树标识。
- Web 应用版本。
- sing-box 版本、平台和编译标签。
- 测试配置的脱敏副本及原文件摘要。
- Clash API 地址及是否启用认证，不记录明文 Secret。
- 测试开始前的核心、TUN、系统代理和系统 DNS 状态。
- 用户确认可在 Codex 失联时独立执行的恢复方式。

所有会影响网络的测试都必须满足：

- 对应配置已通过自动化测试。
- 用户明确同意本次具体操作。
- 一次只改变一个变量。
- 已说明如何判断成功、失败和何时立即停止。

## 6. 单次测试执行流程

每个测试用例按以下流程执行：

1. Codex 提交本次测试编号、目标、前置条件和风险说明。
2. 用户审核并明确同意本次操作。
3. Codex 建立日志目录并记录测试前状态。
4. 用户执行涉及真实核心或网络的操作。
5. Codex 保存相关日志，用户描述观察结果并指出异常。
6. Codex 将结果标记为 `PASS`、`FAIL`、`BLOCKED` 或 `SKIPPED`。
7. 发现 Bug 时，先建立可复现记录和自动化回归测试，再修改代码。
8. 自动化测试通过后，由用户重新执行相同人工用例确认修复。

一个用例结束并完成记录后才能开始下一个用例。

## 7. 日志与测试产物

建议每次会话使用独立目录：

```text
test-artifacts/
└── runtime/
    └── <日期-会话>/
        └── <测试编号>/
            ├── metadata.json
            ├── config.redacted.json
            ├── frontend.log
            ├── api.ndjson
            ├── sing-box.log
            └── result.md
```

各文件用途：

- `metadata.json`：代码版本、系统、sing-box 版本、测试时间和配置摘要。
- `config.redacted.json`：删除密码、Token、私钥和真实节点地址后的配置副本。
- `frontend.log`：浏览器控制台错误和必要的界面事件。
- `api.ndjson`：经脱敏的 API 请求、响应、状态码和 WebSocket 事件。
- `sing-box.log`：本次测试时间范围内的核心日志。
- `result.md`：步骤、预期结果、实际结果、用户反馈和最终状态。

日志目录默认不提交到 Git。不得保存：

- Clash API Secret 或 Authorization 头。
- WebSocket URL 中的明文 Token。
- 订阅地址和订阅凭据。
- 节点密码、UUID、私钥和证书私钥。
- 与问题无关的用户网络流量内容。

## 9. 立即停止条件

出现以下任一情况必须立即停止当前测试：

- 宿主机无法正常联网。
- 默认路由、系统代理或 DNS 出现非预期变化。
- TUN 关闭后接口或路由仍然残留。
- sing-box 出现重复进程、持续重启或无法停止。
- 日志可能泄露密码、Token、私钥或其他敏感信息。
- 实际操作超出本次用户授权范围。

发生网络异常时，由用户执行测试前确认的独立恢复步骤。网络恢复前，Codex 不继续测试或尝试其他网络配置。

## 10. 完成标准

人工测试阶段完成需要满足：

- 计划支持的功能均有明确测试编号和结果。
- 所有高风险操作均由用户明确授权并执行。
- 所有失败项都有可复现步骤和关联日志。
- 已修复问题先通过自动化回归测试，再通过原人工用例复测。
- 系统代理、DNS、TUN、核心进程和网络状态在会话结束后恢复到预期状态。
