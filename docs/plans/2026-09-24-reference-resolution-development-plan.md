# 配置引用职责迁移开发计划

日期：2026-09-24。依据：[前后端职责与配置引用优化方案](../frontend-backend-responsibilities-and-migration.md)。代码基线为 `cb6b6d0`（v0.1.4）。

状态：**计划已落盘，以下开发任务均未开始。** 本次只完善方案和计划，不代表已经修改应用代码或发布新版本。

## 1. 交付目标与顺序

核心目标是让同一份配置在预览、检测、应用、自动重载时都由后端解析引用并生成；前端不再通过读取资源、展开节点、保存草稿来准备这些操作。

| 里程碑 | 对应方案步骤 | 完成结果 | 任务 |
| --- | --- | --- | --- |
| M1：后端统一生成 | 0、1 | 兼容旧档案，直接 API 和自动重载也读取最新引用；生成过程不保存草稿 | T1–T4 |
| M2：浏览器停止同步写回 | 2 | 页面使用后端候选；预览、检测无内部保存；手动应用正常执行一次 | T5–T6 |
| M3：引用模型独立、旧算法退出 | 3、4 | 业务引用不再混在 UI 状态里，前端不再维护配置展开算法 | T7–T8 |
| M4：验收与交付 | 各阶段验收 | 验证行为、兼容和回退，按需构建发布 | T9 |

执行依赖：`T1 → T2 → T3 → T4 → T5 → T6 → T7 → T8`。T9 在 M2、M3 各执行一次对应阶段的交付检查；阶段内已经通过且未受后续改动影响的检查不重复运行。

首个可用交付点是 M2。T7 的新草稿格式和旧客户端拒写协议不阻塞 M1。M1 可以独立提交，正式启用后端解析与 M2 的嵌入式前端配套发布；测试期间采用服务端内部开关，不新增用户设置页面。

## 2. 全程保持的行为

| 操作 | 目标行为 |
| --- | --- |
| 预览 | 基于已保存档案生成候选，不 PUT 草稿、不更新正式目录、不启停核心 |
| 检测 | 基于同一生成流程执行语义检查和 `sing-box check`；只更新检查目录和诊断 |
| 手动应用 | 本请求内生成、检查，成功后提交本次 JSON；不通过内部保存额外触发自动应用或重启 |
| 用户保存档案 | 保留既有 ETag、防抖保存和自动重载设置；只对当前已应用档案按设置执行重载 |
| 源资源更新 | 更新源及依赖状态，不批量重写档案、不直接重载核心 |
| 解绑、复制关联入站 | 固定用户所见候选的原始文本；旧副本恢复需明确选择；保留未知字段和大整数 |
| 历史 sniff | 新增时插入开头，已有托管规则原位更新；保护手工规则，多条规则不强求都在第 0 条 |

生成和检查使用本次取得的入站、订阅内存快照。应用提交检查返回的 JSON，不在提交前另算一份。规则文件仍使用现有固定路径与检查期间的锁，检查后可能被调度器更新；此时标记 `needsApply`，本轮不增加规则文件版本归档或延长锁到提交的新机制。

## 3. 开发任务

### T1：固定旧格式解析契约与对照样例

状态：待开始。依赖：无。完成后进入 T2。

工作范围：

- 以现有 `web/tests/reference-sync.test.ts`、`web/tests/outbounds.test.ts`、`web/tests/inbounds.test.ts` 为来源，整理合成输入和预期输出。建议新增 `internal/configgen/testdata/references/` 存放样例；此路径是计划新增项。
- 用一份行为表标注“保持”“明确报错”“有意改变”，覆盖订阅字段删除、整订阅增删节点、单节点消失、同名冲突、多组复用、过滤、源重排、独立 JSON、旧入站、损坏元数据及 sniff 归属。
- 无引用元数据的旧档案按独立配置处理；声明了引用但必要归属信息不完整时明确报错，不猜测哪些 JSON 是生成节点。
- 区分组类型/成员引用矛盾与生成节点字段差异：前者报错；后者按已建立的来源关系重新生成。记录这对旧客户端手改生成节点及自动重载的影响。
- 固定 JS/Go 过滤兼容样例：空串、普通匹配、非法 JS 正则退回字面匹配、`(?i)hk` 等 Go 可编而 JS 不可编的写法、JS 可用而 Go 不支持的语法。无法等价处理时明确诊断，不能换一套含义继续应用。
- 约定 `resolve_references` 错误阶段及 `code`、`fieldPath`，区分源缺失、节点缺失、过滤不兼容、引用结构矛盾和版本不支持。
- 定义资源摘要覆盖的配置输入。入站摘要须包括影响生成的 mode 和完整配置；订阅摘要须包括有序节点原文。规则、入站、订阅的摘要键区分类型，不依赖 `updatedAt`。

验收：样例有可执行的期望结果；规则集合、别名、未知字段和大整数均可比较；有意改变的行为有明确说明。这里只固定旧格式兼容契约，不引入新档案 schema。

建议提交：`固定配置引用解析的兼容契约与样例`。

### T2：实现后端旧格式适配和纯解析

状态：待开始。依赖：T1。

主要文件：`internal/configgen/` 下新增职责明确的引用适配、解析及测试文件；参考现有 `web/src/features/application/references.ts`、`config-editor/outbound.ts`、`config-editor/inbound.ts`。此时不改前端操作入口。

工作范围：

- 将旧 `editorState` 中的明确引用转换为后端内部模型，只接受支持的版本和字段；纯 UI 字段不参与配置生成。
- 纯解析函数接收档案副本和源快照，返回候选、来源关系及诊断，不自行访问网络、磁盘或保存草稿。
- 按旧格式生成归属完整重建受管节点集合，清除已删除字段和节点，保留独立 JSON；重复执行不能追加重复节点。
- 保持策略组顺序、去重、别名分配和已知引用重映射，缺失源不沿用编辑器的 `keepFallback`。
- 处理关联入站、本地 tag、structured 遗留字段及托管 sniff；新增、更新、删除和多条规则共存分别验证，不重排已有手工规则。
- 候选原文和输出继续使用保留数字精度的表示；不能把现有语义检查中的 `map[string]any` 直接序列化成候选。

验收：T1 样例通过 Go 测试；同一输入、同一快照输出确定；输入未被修改；一个源失败不会返回可应用的半份配置。

回退：代码尚未接入现有操作路径，可直接撤回解析模块的变更。

建议提交：`在后端实现旧档案的配置引用解析`。

### T3：接入所有配置操作入口

状态：待开始。依赖：T2。

主要文件：`internal/configgen/handler.go`、`semantic.go`、`generator.go`、`model.go`，`internal/application/coordinator.go`、`internal/app/server.go`、`internal/capabilities/`；验证位于 `internal/configgen/` 和 `internal/integration/`。

工作范围：

- 增加窄接口读取所需订阅、入站快照，同一资源一次操作只读一次；资源服务通过依赖注入提供读取能力，不形成服务之间的循环调用。
- 将读取档案、读取快照、解析引用、生成候选串接为一个共享准备过程。语义检查、核心检查与最终文件输出消费同一候选，不能再让旧 `buffers` 覆盖新解析结果。
- 预览、检测、手动应用和 `AutoReload` 均接入该过程；自动重载直接调用服务，不绕回 HTTP 保存草稿。
- 保持应用协调器复制本次检测返回的 `Files`，保留草稿修订冲突检查、正式目录漂移保护和失败处理。
- 在现有 capabilities 中增加独立字段，建议名 `serverReferenceResolution`。其返回值必须与所有操作入口的实际启用状态一致，缺失按 false；不复用 `application`。
- 通过同一服务端注入选项控制测试期启用，默认仍走旧路径。新旧输出对照通过后，随 T6 的前端配套交付启用。

验收：关闭浏览器，直接调用预览、检测、应用及自动重载仍能读取源变化；删除的 `detour` 不残留；候选不增加草稿 revision。核心停止和运行两种状态都验证；手动应用不重启，自动重载遵守设置。

回退：恢复旧准备路径；保留检查及应用事务。已执行过的新应用结果不会因回退程序自动恢复，需在测试回退记录中说明。

建议提交：`统一预览检测应用与自动重载的配置生成入口`。

### T4：接入依赖变更和检测过期状态

状态：待开始。依赖：T3。

主要文件：`internal/profile/model.go`、`service.go`，`internal/inbounds/service.go`、`internal/subscriptions/service.go`、`internal/app/server.go`，以及对应服务、集成测试。

工作范围：

- 将本次源摘要与候选摘要关联到检测、应用记录。旧记录缺摘要时不能声称仍与最新源一致；仍按现有机制每次重新检测，不新增跳过核心检查的缓存。
- 入站、订阅保存/删除成功后通知档案依赖状态更新。通知发生在资源写入锁释放后，避免资源服务和档案服务反向持锁；通知失败不能误报源内容未保存，状态在下一次读取或启动时补做核对。
- 启动时核对资源摘要，补回服务关闭期间的变化。仅更新状态，不改写所有引用档案的 JSON。
- 保留规则摘要的兼容入口。不能用一次入站或订阅局部更新覆盖整个资源摘要表，也不能在记录一次较旧快照的应用后清除已知的新资源变更标记。
- 新增诊断元数据保持旧档案输入格式可读，回退兼容通过测试确认；这一任务不引入完整草稿格式迁移。

验收：源变化而 draft revision 不变时，相关档案标记需更新、旧检测显示过期；其他档案不受影响；规则调度更新仍正确；服务重启后状态一致；源修改不自动应用或重启。

建议提交：`跟踪订阅入站依赖并标记过期检测`。

### T5：提供候选视图和保留当前内容的契约

状态：待开始。依赖：T4。此任务在 T6 切换浏览器前完成。

主要文件：`internal/configgen/handler.go`、`model.go`，`internal/profile/handler.go`、`service.go`，`web/src/features/application/types.ts`、`api.ts` 及 API 契约测试。

工作范围：

- 扩展既有预览响应，提供轻量概览：条目身份、本地 tag、类型、来源、是否独立、生成成员、必要的展示字段。不要让页面重新展开完整订阅来计算这些信息。
- 对允许转独立或复制的关联条目，提供未经 JavaScript 数值转换的原始 JSON 文本，并附上档案 ID、revision、候选/源摘要。通过 JSON 字符串承载原文，不能从解析后的 `files[].content` 重新序列化。
- 冻结提交继续沿用带 `If-Match` 的档案保存：用户明确选择的候选文本成为独立输入；后端校验目标条目、关联解除和名称冲突。原文与候选标识作为同一组数据处理，不在保存前重新拉源换成另一份内容。该入站所需的托管 sniff 路由与独立化一并处理，避免解绑后规则丢失；复制后的路由引用使用新本地 tag。
- 复制需要更改 tag 时使用保留其他原始 token 的编辑方式或后端转换，不能把整条候选解析成 JS number 后重写。
- 源已删除时提供明确恢复此前已保存副本的途径；没有候选或副本时提示补充独立配置，不自动填入空对象。失败诊断不把上一次候选标记成最新。
- 明确候选数据仅用于展示和用户主动转独立，不在读取后自动保存；候选响应不能修改草稿 revision。

验收：源端口变化后展示新端口，解绑/复制保持该新值；超出 JS 安全整数范围的字段和未知字段保持原文；切换档案、修改草稿后的迟到响应不能成为本次冻结输入。

建议提交：`提供配置候选概览及原文保留契约`。

### T6：前端切换到后端候选

状态：待开始。依赖：T5。完成后达到 M2 首个可用交付点。

主要文件：`web/src/features/application/`，`config-editor/ConfigWorkspace.vue`、`InboundConfigPanel.vue`、`OutboundConfigPanel.vue` 及相关 JSON 对话框，`features/capabilities/`、`features/inbounds/`、`features/dashboard/`；对应组件和 E2E 测试。

工作范围：

- 能力为 true 时，移除应用操作中的资源拉取、前端展开及同步 PUT。只在草稿已保存且无冲突时允许操作；等待正在进行的用户保存，不在操作内部制造一次保存。
- 预览、检测、应用发出各自请求，显示服务端结果；请求期间禁用重复操作，响应按档案和 revision 归属处理，不覆盖后续本地输入。
- 工作台读取候选概览显示关联字段和生成成员，表单继续编辑用户输入。关联的派生 JSON 显示为只读，用户选择转独立后才能修改，避免修改后又被源覆盖。
- 解绑和复制采用 T5 契约；将入站库整页过期文案和 `internal/inbounds/model.go` 相关注释一并修正。
- 仪表盘运行时继续以核心 API 为准；停止时读取当前选定档案的后端候选并明确显示为待运行/候选，不将草稿旧展开列表或候选误称为运行状态。保留 `hidden` 等展示信息，不改节点切换机制。
- 旧后端缺少能力字段时临时保留旧入口；后端不能依赖浏览器已经刷新才正确解析。该兼容分支在 T8 随支持范围收敛清理。
- 此阶段编辑器保存仍可能保留旧格式生成副本，明确标为过渡实现；最终应用结果已以后端为准，T7–T8 移除该双写路径。

验收：开启自动重载、草稿无待保存编辑时，预览/检测均不发送草稿 PUT、不增加 revision、不更新正式目录、不重启；手动应用正常提交一次，不额外自动应用或重启。源缺失、恢复副本、候选更新后解绑、大整数和旧能力兼容均有浏览器用例。

回退：M2 仍兼容旧档案输入，可恢复旧前端入口，但会恢复浏览器同步保存的限制；新后端不能同时把旧生成结果当作独立条目重复追加。

建议提交：`前端改用后端候选并取消配置操作前同步保存`。

### T7：迁移业务引用的持久化模型

状态：待开始。依赖：M2 验收通过。此前不实现本任务的新 schema 拒写机制。

主要文件：`internal/profile/model.go`、`service.go`、`store.go`，后端引用适配器，前端 `features/profiles/types.ts`、`api.ts` 和编辑器保存入口；迁移测试使用隔离数据。

工作范围：

- 确定并记录新格式契约：独立 JSON、业务引用、策略组参数、顺序、生成归属与纯 UI 状态的存放位置；只保留一个权威生成输入。
- 将明确存在的来源 ID、过滤、别名、组引用和 sniff 归属迁出 `editorState`。只删除能够确认归属的旧生成副本，不按同名或内容相似猜测来源。
- 读取旧格式只做内存适配；保存或复制时按版本和 ETag 原子写入。复制档案与复制单条入站保持各自语义，不能因为复用迁移代码混为一种操作。
- 新格式写入时要求客户端声明所支持版本；缺失或过旧的客户端不得覆盖新引用。仅拒绝不兼容写入，不把合法旧档案无理由变成无法打开。
- 在新格式首次写入前完成备份和回退演练，明确如何保留迁移后的修改；不能只通过换旧二进制宣称已回退。

验收：关联、独立、混合、损坏元数据和无来源旧入站都有迁移样例；迁移重复执行结果不变；打开不产生写入；复制、保存、检测通过；旧客户端不会清掉新字段；源更新不再需要回刷档案展开副本。

建议提交：`将配置业务引用迁出编辑器状态并兼容旧档案`。

### T8：删除前端旧生成逻辑并收敛依赖

状态：待开始。依赖：T7。

主要文件：`web/src/features/application/references.ts`，`config-editor/outbound.ts`、`inbound.ts`、`use-outbound-editor.ts`、编辑器保存入口，`dashboard/proxy-groups.ts` 及相关测试。

工作范围：

- 删除前端仍在执行的订阅展开、生成节点归属重建、引用重映射、sniff 生成及依赖完整资源的同步缓存。
- 把需要保留的表单值处理、显示类型、tag 展示和 UI 状态分离出来；正常复用纯表单和公共组件，不为“页面独立”复制一套组件。

- 算法边界由 Go 测试覆盖，前端保留交互和请求契约测试，不同时维护两套生成算法的长期测试实现。

验收：应用操作、编辑器保存、仪表盘展示均不再执行前端展开算法；纯表单与 JSON 编辑仍可用。调整一条生成规则时，业务算法只需修改后端；API/交互未变化时无需跟着改页面。

建议提交：`移除前端重复生成逻辑并收敛展示依赖`。

### T9：阶段验收与交付记录

状态：待开始。依赖：M2 或 M3 对应任务完成。

执行范围：

- Go 变更运行 `go test -race ./...` 和 `go vet ./...`，包含直接 API、自动重载、资源变更、并发保存和迁移测试。
- 前端变更运行 `npm --prefix web run typecheck`、`npm --prefix web run test:unit`、`npm --prefix web run test:e2e`。UI 按项目规则检查桌面/平板/手机、浅/深色、导航、对话框与键盘操作。
- 按下节场景逐项记录结果、对应测试和已知限制；真实核心契约测试仅在项目指定二进制选择有效且可用时执行。
- 所有测试使用隔离档案、假核心或项目规定的测试核心，不使用 `Release/` 运行数据试迁移。
- 同步 README 和职责文档中的“当前/目标”表述；只有已完成验收的步骤才能标记完成。
- 有实际发布任务时递增版本，同步 `web/package.json` 与锁文件，通过 `sh scripts/build.sh` 生成并验证 `dist/singbox-web-v<version>`；不复用旧版本，不部署或管理 `Release/`。

回退检查：M2 记录旧格式兼容和已产生正式配置的处理方式；M3 验证程序与数据配套恢复，并保留迁移后的用户编辑。每个任务在必要检查通过后使用中文本地提交，保持当前工作目录和分支。

## 5. 范围与完成判定

先完成统一后端生成与取消浏览器同步写回，再迁移格式、删除旧算法。正则兼容、大整数、候选内容保留属于完成迁移所需的约束；新草稿格式只在 T7 引入。

DNS/路由全部表单重做、远程订阅抓取、事件总线、微服务、规则文件长期历史、源修改后立即重载、全局弹窗或保存机制重构均不随本计划扩展。

M2 完成表示“所有操作由后端生成、页面不为预览/检测/应用保存派生结果”；M3 完成表示“业务引用独立持久化、前端旧生成算法已删除”。不能只以文件数量减少、某一按钮可用或测试总数增加判定完成。
